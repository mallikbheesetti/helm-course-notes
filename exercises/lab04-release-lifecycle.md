# Lab 04 - Release Lifecycle

## Goal

Practice install, upgrade, history, rollback, status, inspection, and
uninstall using the chart generated by `helm create`.

## Prerequisites

- Working cluster
- Lab 03 completed

## Tasks

1. Create a scratch chart:

   ```bash
   cd ~/helm-labs
   helm create lifecycle
   cd lifecycle
   helm lint .
   helm template demo .
   ```

2. Install release `demo` in namespace `lab04`:

   ```bash
   helm install demo . -n lab04 --create-namespace
   helm list -n lab04
   helm status demo -n lab04
   ```

3. Inspect the release:

   ```bash
   helm history demo -n lab04
   helm get all demo -n lab04
   helm get manifest demo -n lab04
   helm get values demo -n lab04
   ```

4. Upgrade with a changed value:

   ```bash
   helm upgrade demo . -n lab04 --set replicaCount=3
   helm history demo -n lab04
   ```

5. Upgrade again with a different value:

   ```bash
   helm upgrade demo . -n lab04 --set replicaCount=2 --set service.type=NodePort
   helm history demo -n lab04
   ```

6. Roll back to revision 1:

   ```bash
   helm rollback demo 1 -n lab04
   helm history demo -n lab04
   helm get values demo -n lab04
   ```

7. Uninstall while keeping history:

   ```bash
   helm uninstall demo -n lab04 --keep-history
   helm list -n lab04 --uninstalled
   helm history demo -n lab04
   ```

8. Reinstall using `--generate-name`:

   ```bash
   helm install . -n lab04 --generate-name
   helm list -n lab04
   ```

9. Clean up all releases in the namespace:

   ```bash
   helm list -n lab04
   helm uninstall <release> -n lab04
   kubectl delete namespace lab04
   ```

## Hints

- `helm upgrade` may skip creating a revision if nothing rendered changed.
- `helm rollback` creates a new revision representing the restored state.
- `--keep-history` preserves release metadata after deleting live objects.
- `helm get values` shows values supplied by the user, not all computed
  defaults (use `--all` to include computed values).

## Verify

```bash
helm history demo -n lab04
kubectl get deploy -n lab04
kubectl get svc -n lab04
```

At each step, the history should show a new revision with a meaningful
description (`Install`, `Upgrade`, `Rollback`, `Uninstall`).

## Solution sketch

```bash
helm create lifecycle
helm install demo ./lifecycle -n lab04 --create-namespace
helm upgrade demo ./lifecycle -n lab04 --set replicaCount=3
helm history demo -n lab04
helm rollback demo 1 -n lab04
helm uninstall demo -n lab04 --keep-history
helm list -n lab04 --uninstalled
```

## Stretch

- Use `helm upgrade --install` on a non-existent release.
- Compare `helm get values demo --all` with the chart defaults.
- Delete a Deployment manually, then run `helm upgrade` and observe what
  Helm restores.
- Run `helm template demo ./lifecycle --set service.type=NodePort` and
  find the rendered Service type.

## Reflection

What is the difference between a release revision and a chart version?
What does a rollback actually change?
